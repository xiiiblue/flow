# 怎样把问题说清楚

用户提供已知事实就足够。比如：“我筛选了这个月的37条工单，导出后只有第一页的20条。我希望保留筛选条件，拿到全部37条。”这样，接手的人马上知道该查哪里、该用什么结果作比较。

## 要提供哪些信息

- 说清在哪个页面、做了哪一步、实际看到了什么。如果只是想知道用法，直接说你想做什么。
- 写出你期待的结果。若某些人、某类数据或某个时间段才会出问题，也一起说明。
- 补充上次反馈时，带上问题编号或指明上一条消息。截图可只保留有关区域，遮住员工和客户资料。

## 接下来会发生什么

QueenBee在当前会话回答用法，或询问一两条关键线索。有足够依据登记时，助手先查有没有相同问题，保存后再读回真实编号。登记通知会告诉你目前查到了什么；是否值得改、允许做到哪一步，由负责人决定。

有了问题编号，后续可以查原问题单。评审结果、代码待审、交付和正式受阻等消息，由通知助手在项目固定的回执群提醒提出人。详见[通知发到哪里](/flow/read/receipts/)。
