# 内容来源与网站维护

本页供网站维护者查阅。第一次了解HiveFlow，可以先读[认识HiveFlow](/flow/read/introduction/)或[一条反馈怎样处理](/flow/read/workflow/)。

## 内容依据

网站依据蜂巢项目中的HiveFlow介绍手册整理，使用同版本规范核对规则和适用范围。来源版本、采用章节和原始文件摘要保存在[来源记录](https://github.com/xiiiblue/flow/blob/main/src/data/source.json)中。

网页按读者的问题重新组织内容。原始手册、公开网页和执行规则各有用途：手册解释做法，网页帮助读者理解，目标项目当前规则决定实际任务怎样执行。网页修改不能改变正式规则，也不能凭介绍文字允许真实业务操作。

## 读者应该先看到什么

开头直接说明HiveFlow是什么、想解决什么问题。随后用一件具体的事讲清用户、负责人和助手分别做什么，再介绍工具和接入条件。

工具名称第一次出现时解释用途。例如，Issue是一条待处理问题记录，PR是代码审阅请求。机器分工、配置字段、规则编号和网站维护过程，放在需要查阅的地方。

来源记录需要保留，正文应围绕读者的任务写。不要把材料导入过程、维护日志或文件摘要当成产品介绍。教学案例标明示例，未验证的能力写清状态和记录日期。

## 更新时怎样核对

1. 先读网站仓库的维护规则，检查分支、工作树和已有修改。
2. 核对来源手册和对应规范。规则变化先在负责规则的项目中确认；只改网页表达时，保留原含义。
3. 按阅读需要改写。保留授权条件、教学示例和未验证范围，检查是否夹带私人消息、真实身份、配置或凭据。
4. 更新来源记录，保留原始文件摘要；改写稿不能冒充源文件原文。
5. 运行构建、链接和内容检查。涉及页面显示或交互时，检查桌面、手机、明暗主题和打印。
6. 分别报告本地修改、检查、提交和发布状态。构建通过不代表网站已经发布，也不代表业务流程已经验证。

## 公开项目与许可

[公开项目hive-flow](https://github.com/xiiiblue/hive-flow)提供规范参考、介绍和离线工具；[网站源码flow](https://github.com/xiiiblue/flow)保存本站内容和网页实现。两者分别采用Apache-2.0，各自保留LICENSE与NOTICE及第三方声明。

公开内容不包含私有HiveOS未分发材料，也不提供真实业务环境的访问权限。网站可独立阅读，无需访问私有仓库。
